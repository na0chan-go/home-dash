# TRIAGE

## 目的

`OPS_LOG` の記録を週1回Issue化し、優先度を揃えて次の改善候補を絞るための手順です。

## 週1回の手順

1. `docs/OPS_LOG.md` から今週の記録を読み返す
2. 同じ問題を1つの論点にまとめる
3. 論点ごとにIssueを起票する（最大3件まで）
4. 各Issueにラベルを付ける（`type` / `area` / `priority`）
5. `docs/WEEKLY_REVIEW.md` に採用/見送りを記録する

## Issue起票時のラベルルール

- `type`: `type: bug` / `type: enhancement` / `type: docs`
- `area`: `area: ui` / `area: api` / `area: ops`
- `priority`: `priority: p0` / `priority: p1` / `priority: p2`

## 優先度の目安

- `p0`: 利用継続を妨げる（操作不能、頻繁なエラー）
- `p1`: 毎日使うとストレスが高い
- `p2`: あれば嬉しい改善

## MVP0逸脱チェック

Issue起票時に必ず確認すること:

- 連絡 / 買い物 / ゴミの体験改善に直接つながるか
- 天気/室温/株価/献立/在庫/IoTなどへ広がっていないか
- 運用コストが過剰に増えないか

## やらないこと（明文化）

- 在庫管理など入力負荷が高い機能を安易に追加しない
- 「便利そう」だけでスコープを拡大しない
- 1週間で着手するIssueを3件超にしない

## 1週間の着手上限

- 着手するIssueは **最大3件** まで
- 4件目以降は次週へ繰り越す
